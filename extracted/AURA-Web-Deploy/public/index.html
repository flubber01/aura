Routing policy

Clear priority rules and stable fallback behaviour

POLICY

1 · Private admin keys

Use first when enabled, budget permits and the provider probe passes.

PRIORITY 1

2 · Approved shared/public routes

Use only where terms allow it; respect quotas and avoid rotating around access limits.

PRIORITY 2

3 · Local fallback

Use a configured local model when cloud routes are unavailable.

PRIORITY 3
⌁
Secret handling

Store keys in a secret manager or environment variables; persist only key IDs, scopes, provider, tier and health statistics in the database. Encrypt stored values if storage is unavoidable.

Three-response scoring rubric

Configured for the master brain’s pick-and-fallback loop

Task fit35%
Correctness / evidence30%
Safety / rights20%
Latency / cost15%

The judge should reject invalid JSON, missing evidence, disallowed actions and low-confidence outputs before comparing scores. A fallback is triggered by a failed validation or execution health check, not by cosmetic score changes alone.
